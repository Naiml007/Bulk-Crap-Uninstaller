# Win11 theme tokens, DWM title bar / Mica, and owner-drawn control set (v2)

This is the second review pass. Issues 1 (Win11TextBox ignores ThemeChanged), 2 (secondary windows missing ApplyTheme), 4 (ThemeChanged subscription never removed), and 5 (Win11CheckBox per-paint font allocation) from the v1 review are all fixed. Issue 3 (partial checkbox substitution) is partially addressed: `checkBoxEnableExternal`, the six app-store checkboxes, `checkBoxRemovable`, and `checkBoxAutoInstallFolderDetect` are now converted. Four checkboxes on the Detection tab remain plain `CheckBox` and will render inconsistently next to Win11-styled controls on the same page.

**Watch for:** (confirmed) `SettingsWindow.Designer.cs` lines 89, 99–101 still instantiate `checkBoxScanWinUpdates`, `checkBoxScanRegistry`, `checkBoxScanDrives`, and `checkBoxPreDefined` as the system `CheckBox` type. These sit in `groupBoxAppStores` and `groupBox1` alongside `Win11CheckBox` controls. (confirmed) `Win11TextBox` unsubscribes from `ThemeChanged` in `Dispose` but no other form unsubscribes its handler in `Dispose` — all five forms rely solely on `FormClosed`. On a form that is hidden without being closed, the handler fires against a hidden window's handle. (possible) `Win11DwmHelper.ApplyTheme` is called with `form.Handle` before the form is shown; on some Windows versions, forcing handle creation before `Show()` can suppress the initial Mica compositor attachment.

**Verdict**: NEEDS_CHANGES

## High-level view

The five v1 fixes are clean. `Win11TextBox` now subscribes a named handler (`OnThemeChanged`) and unsubscribes it in `Dispose`, which is the correct pattern. All four secondary forms call `Win11DwmHelper.ApplyTheme` in their constructors and store a local `themeHandler` variable captured by the `FormClosed` unsubscribe lambda — this closes the title-bar gap and the subscription leak from v1.

The checkbox substitution is now nearly complete. `checkBoxEnableExternal`, `checkBoxRemovable`, `checkBoxAutoInstallFolderDetect`, and the six app-store/scoop/oculus/choco checkboxes are all converted. What remains is `checkBoxScanWinUpdates` (line 89), `checkBoxScanRegistry`, `checkBoxScanDrives`, and `checkBoxPreDefined` (lines 99–101). `checkBoxScanWinUpdates` is in the same `groupBoxAppStores` as several `Win11CheckBox` controls, so the visual mismatch is visible within a single group box.

The `Dispose`-vs-`FormClosed` asymmetry is new in this pass. `Win11TextBox` unsubscribes in `Dispose` (correct), but each form's `themeHandler` is only unsubscribed when `FormClosed` fires. If a form is ever shown, hidden with `Hide()`, and then shown again, the subscription survives correctly — but if the form is disposed without `Close()` being called (e.g. via `using` or `GC`), the lambda holds a live delegate on the static event. For `MainWindow` this doesn't apply (it stores `_themeChangedHandler` and unsubscribes on `FormClosed`), but `JunkRemoveWindow`, `SettingsWindow`, `UninstallProgressWindow`, and `BeginUninstallTaskWizard` all use the local-variable capture pattern where `Dispose` does not clean up.

The DWM apply-before-show concern is low severity but worth noting: `ApplyTheme` is called in the constructor, before `Show()` or `ShowDialog()`. On some Windows builds, applying `DWMWA_SYSTEMBACKDROP_TYPE` while the HWND has not yet been presented can silently no-op. A safer hook point is `OnHandleCreated`, which fires after the HWND is created but still before the window is painted.

<summary>Issues (3)</summary>

1. **Four checkboxes still unconverted in SettingsWindow** — `checkBoxScanWinUpdates`, `checkBoxScanRegistry`, `checkBoxScanDrives`, and `checkBoxPreDefined` remain as `System.Windows.Forms.CheckBox`. `checkBoxScanWinUpdates` is in the same group box as converted controls. Convert the remaining four following the same substitution pattern already applied to the other 20+ checkboxes in the same file.

2. **Secondary form ThemeChanged handlers not removed on Dispose** — `JunkRemoveWindow`, `SettingsWindow`, `UninstallProgressWindow`, and `BeginUninstallTaskWizard` unsubscribe via `FormClosed`. If any of these forms is disposed without `Close()` (e.g., via `using` or parent disposal), the lambda delegate stays on the static `Win11Theme.ThemeChanged` event. Fix: override `Dispose(bool disposing)` in each form and unsubscribe there, the same way `Win11TextBox` does. Alternatively, store the handler in a field (like `MainWindow` does with `_themeChangedHandler`) and add a `Dispose` override.

3. **DWM theme applied before window is shown** — `ApplyTheme(this)` is called in each form's constructor, before `Show()` or `ShowDialog()`. On affected Windows builds, `DWMSBT_MAINWINDOW` applied to an HWND that hasn't been presented may silently no-op, leaving the Mica backdrop absent until the next theme-change event. Fix: move the `ApplyTheme` call (and the `ThemeChanged` subscription) to an `OnHandleCreated` override, or at minimum call it again in `OnLoad`.

### Remaining plain CheckBox controls in SettingsWindow

The diff converts `checkBoxEnableExternal` (line 72) and all app-store / folder detection checkboxes. Left unconverted:

- `checkBoxScanWinUpdates` — instantiated at line 89, inside `groupBoxAppStores` which also contains `Win11CheckBox` controls for Steam, Store Apps, Win Features, Scoop, Oculus, and Choco.
- `checkBoxScanRegistry`, `checkBoxScanDrives`, `checkBoxPreDefined` — lines 99–101, inside `groupBox1` (the "Registry and file system" group).

The `groupBoxAppStores` case is the most visible: within the same group box, six checkboxes have rounded Win11 glyphs and one has the system glyph.

### ThemeChanged subscription lifetime across form types

`Win11TextBox.Dispose(bool disposing)` correctly removes the subscription before `base.Dispose`. The five forms use a different pattern: `FormClosed += (s, e) => Win11Theme.ThemeChanged -= handler`. `FormClosed` fires when the user or code closes the form; it does not fire if the form object is disposed directly (e.g., `form.Dispose()` called without `Close()`). `MainWindow` avoids this by storing `_themeChangedHandler` as a field, which could also be unsubscribed in a `Dispose` override — but `MainWindow` itself doesn't have that override either. For forms that can be instantiated multiple times (`JunkRemoveWindow`, `BeginUninstallTaskWizard`), each instance that is disposed without `Close()` leaks one delegate on the static event.

### DWM handle-creation timing

WinForms creates the underlying HWND lazily — it may not exist at the point `ApplyTheme(this)` is called in the constructor. Accessing `form.Handle` in the constructor forces early HWND creation, which is harmless but can interact with some accessibility and theming infrastructure. More importantly, `DWMSBT_MAINWINDOW` requires the compositor to have associated a swap chain with the window, which may not have happened yet. `OnHandleCreated` is the idiomatic hook point for DWM calls, as the HWND is guaranteed to exist and the compositor has started associating resources with it.
